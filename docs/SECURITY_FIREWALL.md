# Command Safety Firewall

The Command Safety Firewall is the mandatory, single boundary between the application and every
SSH session to an OmniSwitch. Its rule:

> **The application never executes a CLI command unless the command was generated by the
> firewall from the authoritative policy, validated twice, and belongs to a permitted operation.**
>
> NO COMMAND IN ALLOWLIST = COMMAND BLOCKED.

Code: [`backend/app/security/`](../backend/app/security/).
Tests: `test_firewall.py`, `test_security_api.py`, `test_safety_modes.py`, `test_port_restart.py`,
`test_rbac_simple.py`, `test_platform.py`, `test_architecture.py`.

## 1. Refactor inventory: every path that could generate or send a command

Before this refactor there was already a single guard (`GuardedSession`), but it had gaps.
The audit found the following:

| # | Location (before) | What it did | Gap | Now |
|---|---|---|---|---|
| 1 | `services/ssh/manager.py` `GuardedSession.run(text)` | string guard: "looks like `show …`" | any harmless-looking `show` text passed (e.g. `show configuration`); no operation binding, budget, fingerprint | **Removed.** Replaced by `FirewallSession`, which has no method that accepts text |
| 2 | `services/ssh/manager.py` `SwitchConnector.open_raw()` | public, returned an **unguarded** transport | bypass path | **Removed.** Private `_open_transport()`; `session()` only yields a `FirewallSession` |
| 3 | `services/ssh/asyncssh_session.py` `AsyncSshCliSession.run(text)` | sent any text | anyone holding the object could send text | Replaced by `run_approved(request)`, which **verifies the HMAC seal** (`assert_sealed`) |
| 4 | `simulator/session.py` `SimulatedCliSession.run(text)` | same as #3 (lab) | same | same as #3 |
| 5 | `services/alcatel/adapter.py` `read_system_info(session, command="show system")` | discovery with a **raw command parameter** | arbitrary text parameter | **Removed.** `FirewallSession.discover()` uses the separate `DISCOVERY_PROFILE` |
| 6 | `services/alcatel/commands.py` `render()` / `render_bounce()` | second, independent rendering path | policy scattered in 2 places | **Removed.** Rendering exists only in `firewall.build()` |
| 7 | `services/alcatel/profiles.py` `WRITE_GRAMMAR` + regex linter | its own allowlist | second policy | Now delegates to `security/policy.py` (the only policy) |
| 8 | `services/port_control/service.py` `s.run(down_cmd)` / `s.run(up_cmd)` | sent pre-rendered strings in a PORT_CONTROL session | strings travelled through business code | `fs.restart(authorization)` → `down()` / `up()`; firewall builds the text |
| 9 | `services/ssh/cli.py` `InteractiveCli` keystrokes | sends `"\n"` (silent login prompt) and `" "` (pager) | terminal keystrokes, not commands | Unchanged. Only callable by the two transports (enforced by `test_architecture.py`) |
| 10 | `simulator/ssh_server.py` | server side of the lab SSH simulator | n/a (receives commands) | unchanged |

After the refactor, `test_architecture.py` statically verifies that:

- only the transports call `cli.run(`;
- only the firewall calls `run_approved(`;
- transports verify the seal and expose no `run()`;
- only the manager opens transports;
- none of the removed APIs still exist;
- no LLM SDK is imported;
- no API request model accepts a command field;
- the UI has no terminal or console.

## 2. Architecture

```
WEB UI ─► API (auth, CSRF, role) ─► BUSINESS LOGIC (search, port query, restart)
        ─► OPERATION POLICY (COMMAND_POLICIES)     ◄── security/policy.py (single source)
        ─► COMMAND SAFETY FIREWALL                  ◄── security/firewall.py
             validators ─ allowlist ─ AOS profile ─ risk ─ seal ─ final check ─ modes ─ budget
        ─► TRANSPORT.run_approved(sealed request)   (re-verifies the seal)
        ─► SSH ─► OmniSwitch
```

The request-level **CommandFieldGuard** (ASGI) rejects any JSON body that carries a
command-like key (`command`, `cli`, `exec`, `shell`, …) before routing. All request schemas also
use `extra="forbid"`, so unknown fields cause a 422 and are never silently ignored.

## 3. Operations (the complete list)

| Operation | Risk | Allowed roles | Max commands | Commands (keys → allowlisted templates) |
|---|---|---|---|---|
| `SEARCH_MAC` | READ_ONLY | all | 1 | `mac_lookup` |
| `GET_PORT_VLAN` | READ_ONLY | all | 1 | `vlan_port` / `vlan_linkagg` |
| `GET_PORT_STATUS` | READ_ONLY | all | 2 | `port_detail` + `port_admin`. The verified profiles need two `show` commands |
| `GET_LLDP` | READ_ONLY | all | 1 | `lldp_port` |
| `GET_PORT_MACS` | READ_ONLY | all | 1 | `mac_on_port` |
| `RESTART_PORT` | STATE_CHANGING | operator, admin, mac_operator | 3 per authorization | `bounce_down` ≤1, `bounce_up` ≤2 (one restore attempt after a read-back) |
| `DISCOVER_SYSTEM` (internal) | READ_ONLY | all | 1 | `system_info` = `show system` (separate `DISCOVERY_PROFILE`) |

"Allowed roles" is the firewall's own check. Which *API* a role may call is decided separately by
the permission model (see [SECURITY.md](SECURITY.md#3-rbac)): a `mac_operator`, for example, can reach
`SEARCH_MAC` and `RESTART_PORT` only through the simplified `/api/simple` endpoints, and only
for a High-confidence ACCESS port on an access switch that passes the endpoint evidence gate
([SECURITY.md § 4](SECURITY.md#4-mac_operator-direct-endpoint-restart)).

Explicitly denied, and recorded as security events when requested:

- CONFIGURATION
- VLAN_CREATION / VLAN_DELETION / VLAN_MODIFICATION
- ROUTING_CONFIGURATION / STP_CONFIGURATION / IP_CONFIGURATION / INTERFACE_CONFIGURATION
- USER_CONFIGURATION / PASSWORD_CONFIGURATION / SYSTEM_CONFIGURATION
- REBOOT_SWITCH / WRITE_MEMORY / COPY_CONFIGURATION / DELETE_CONFIGURATION / FIRMWARE_UPGRADE
- EXECUTE_COMMAND / CLI / SHELL / TERMINAL

The template allowlist contains the exact literals from the ALE guides, for example
`show mac-learning mac-address {mac}` (AOS 8) and `show mac-address-table {mac}` (AOS 6). The
only state-changing pairs are the four port-bounce strategies. Custom command profiles can only
**choose among** allowlisted templates. Adding a new command requires a reviewed code change.

## 4. The pipeline (every command)

| Step | Where | On failure |
|---|---|---|
| Authentication, CSRF, permission | API layer (`require(Permission…)`) | 401/403; a `mac_operator` probing a technical API is audited as `RBAC_VIOLATION` (HIGH) |
| Command-field guard / strict schemas | request_guard.py, schemas | 400 HIGH / 422 |
| Operation known and in policy | `firewall._build` | BLOCKED, WARNING (`UNKNOWN_OPERATION`) |
| Role in the operation's allowed roles | `_build` | BLOCKED, HIGH |
| Command key belongs to the operation; exact parameter set | `_build` | BLOCKED, HIGH (`COMMAND_NOT_ALLOWED`) |
| Profile enabled, command verified, template on allowlist | `accept_profile`, `_build` | BLOCKED |
| **Profile applies to this exact model family and AOS version** | `check_applicability` (at `bind_profile`) | BLOCKED: "Command profile unavailable for this switch model/version" |
| **Administrator lab verification** for that model family + version (real SSH switches; the capability is `READ`) | `check_applicability` | BLOCKED (`PROFILE_NOT_LAB_VERIFIED`) |
| Parameter validation (MAC, port, agg) | `validators.py` | BLOCKED; injection chars → HIGH (`INJECTION_ATTEMPT`), malformed → INFO |
| Command generation, risk classification = operation's risk | `_build`, `risk.py` | BLOCKED; DANGEROUS → CRITICAL |
| Seal (HMAC-SHA256, per-process secret) and **fingerprint = SHA-256(command, switch, operation, profile)** | `_build` | n/a |
| Final validation: seal, session binding, re-render equals text, allowlist, risk, fingerprint | `final_check` | BLOCKED, CRITICAL |
| Safety state for state-changing commands (mode, kill switch, SAFE MODE, role) | `_execute` | BLOCKED (restore exemption, see §6) |
| Budgets: per operation, per authorization, **per session (60 commands, `SSH_MAX_SESSION_SECONDS`)** | invocations, `_check_limits` | BLOCKED (`COMMAND_BUDGET_EXCEEDED`, `SESSION_LIMIT`) |
| Transport re-verifies the seal | `assert_sealed` | BLOCKED, CRITICAL |
| **Output contract**: the answer must match the command's documented format (state-changing commands must print nothing) | `_execute` | `UNEXPECTED CLI OUTPUT`: result discarded, alert, circuit-breaker count |

**Fail closed.** Several conditions block commands:

- Any unexpected exception inside a check is converted to `COMMAND BLOCKED` (CRITICAL
  `SAFETY_CHECK_ERROR`).
- If the policy integrity self-check fails at startup, the firewall is `FAILED` and every command
  is blocked. `/api/health` reports `degraded`, and the UI shows a red banner.
- If the safety state cannot be read from the database, it is treated as locked, and all
  state-changing commands are blocked.
- If the verification records cannot be read, the profile counts as unverified.
- If the model or AOS version is known but no verified profile applies, the switch is not
  connected to at all. If the version is unknown, only the discovery command runs.
- `NETWORK_COMMAND_EXECUTION` engages the kill switch for any value other than exactly `ENABLED`.

**No automatic fallback, no blind retry.** No code path tries command A and then command B. The
down command is never re-sent. The restore (`bounce_up`) is sent at most twice per authorization,
and a second attempt, or an attempt after an ambiguous timeout, is made only after the port's
admin state has been read back (see §5).

## 5. RESTART_PORT

1. **Prepare** (read-only):
   - verify the user, switch, port and MAC;
   - re-read VLANs, status, LLDP and MAC count, then classify (including topology evidence);
   - store a **plan snapshot** of the port;
   - apply the restart policy (role, classification, confidence, switch topology role, mode);
   - run the **COMMAND SAFETY TEST**, which generates and validates the exact commands without
     any way to send them.
2. **Execute:**
   - the plan must belong to this user and must not have expired;
   - the confirmation must match exactly: `RESTART PORT <port>` (plus
     `I UNDERSTAND THIS IS A TRUNK` for an EMERGENCY trunk override). The simplified
     `mac_operator` flow has no typed phrase and no administrator approval, but it is limited to
     High-confidence ACCESS ports on access switches that pass the endpoint evidence gate (re-run
     immediately before the change);
   - the safety state must allow it: MAINTENANCE mode (EMERGENCY for administrators), no kill
     switch, no SAFE MODE. Otherwise the result is PORT RESTART BLOCKED, and the safety test
     report is stored;
   - dry-run, or a strategy not lab-verified for this model family and AOS version, means NO
     COMMAND is SENT;
   - the per-user rate limit (default 3 per 10 min) and the same-port interval (default 60 s)
     must pass;
   - the **switch lock and port lock** (`operation_locks`, taken atomically) must be free;
   - the firewall re-checks everything it can (role, mode, policy, strategy verification) and
     issues a sealed **RestartAuthorization**, bound to the switch, port, profile, strategy and
     user, and expiring after 15 minutes.
3. **Bounce** (background, shielded from request cancellation):
   - **pre-restart re-verification**: the port is read again and compared with the plan snapshot
     (MAC location, classification, VLANs, LLDP neighbors, admin/oper state). Any difference →
     "Network state changed since confirmation. Operation cancelled for safety." Nothing is sent;
   - a **before snapshot** is stored;
   - `down()` → hold → `up()` through the firewall;
   - **ambiguous results**: if the down command gets no answer, it is never re-sent. On a new
     session the admin state is read: if the port is enabled, nothing else is sent; if it is
     disabled (or unreadable), the restore is sent;
   - **post-restart verification**: port UP, MAC relearned, VLANs, LLDP and classification, stored
     as the **after snapshot**. A missing MAC is reported as "WARNING: MAC has not been relearned"
     and raises an alert;
   - the audit entry records role, operation, VLAN, profile, fingerprint, risk, approval, error,
     and the before/after state. `GET /api/ports/actions/{id}/report` returns the change report.

Classification policy:

| Port | MAC_OPERATOR | OPERATOR | ADMIN |
|---|---|---|---|
| ACCESS, High confidence, access switch, endpoint evidence gate passed | yes, simple confirmation | `RESTART PORT <port>` | `RESTART PORT <port>` |
| ACCESS otherwise (Medium confidence, switch role not `access`, gate failed) | no | `RESTART PORT <port>` | `RESTART PORT <port>` |
| administratively disabled port | no | no | no (a bounce would enable it) |
| LIKELY_ACCESS | no | phrase + warning | phrase + warning |
| UNKNOWN | no | no | no (fail closed) |
| TRUNK / LIKELY_TRUNK, or any port of a core/distribution switch | no | no | EMERGENCY mode only: HIGH RISK + two phrases |
| Declared uplink / link aggregate | no | no | no (hard block) |

## 6. Operation modes, kill switch, circuit breaker

| Control | How it is set | Effect |
|---|---|---|
| **NORMAL** mode (default) | Safety Controls (admin, reason required) | read-only operations; restarts can be prepared and simulated, never executed |
| **MAINTENANCE** mode | Safety Controls | authorized state-changing operations with every check |
| **READ_ONLY** mode | Safety Controls, or forced by `READ_ONLY_MODE=true` | no state changes at all |
| **EMERGENCY** mode | Safety Controls | administrators only; enables the audited trunk/infrastructure override |
| **Kill switch** "STOP ALL NETWORK OPERATIONS" | operators and admins may engage it; only admins release it; forced by `NETWORK_COMMAND_EXECUTION≠ENABLED` | every state-changing command blocked immediately; reads continue |
| **SAFE MODE** (circuit breaker) | tripped automatically; reset by an admin with a reason | state changes blocked until reset |

The circuit breaker counts, within a window (default 10 minutes): SSH failures of switches that
were previously healthy (default 5, `CIRCUIT_BREAKER_THRESHOLD`), authentication failures
(3), HIGH/CRITICAL validation failures (3) and unexpected CLI answers (3). Failures of switches
already known to be offline are not counted, so a dead switch cannot hold the platform in SAFE
MODE. SAFE MODE is stored in the database and survives restarts.

Every change of mode, kill switch or SAFE MODE is written as a `safety_events` row **and** an
audit entry. These keys cannot be changed through the generic settings API.

**Restore exemption.** If the kill switch or a mode change happens *after* a restart has taken the
port down, the restore (`up`) command of that same authorization is still sent. Leaving a port down
would be the unsafe outcome. Any new `down` is blocked. This is logged as a SECURITY event.

## 7. Records, alerts and audit

- **SSH sessions** (`ssh_sessions`) store, for every session, the user and purpose, the
  operations, commands attempted/executed/blocked, the result, and a per-command list of
  operation, command key, **fingerprint**, risk, status and duration. The command text is not
  stored in the session log.
- **Audit log** (`audit_logs`) is **append-only**: database triggers reject UPDATE and DELETE
  (and TRUNCATE on PostgreSQL). Entries carry user, role, source IP, operation, switch, port,
  MAC, VLAN, profile, command fingerprint, risk level, approval, result, error, and before/after
  state. Severities:
  - INFO: invalid MAC or other malformed parameter;
  - WARNING: unknown operation, safety-mode block, rate limit, mode change;
  - HIGH: shell characters in a parameter, arbitrary command field, role violation, budget
    exceeded, EMERGENCY mode, breaker reset;
  - CRITICAL: forged or unsealed command, dangerous risk class, safety-check error, kill switch,
    breaker trip, a port that may still be down.
- **Alerts** (`alerts`, deduplicated for 60 minutes): multiple edge locations, MAC move,
  undeclared trunk-like port, NetBox mismatch, SSH failure, circuit breaker, blocked dangerous
  operation, failed restart, MAC not relearned, unexpected CLI output, kill switch, EMERGENCY
  mode. Alerts never trigger an action.
- **Port snapshots** (`port_snapshots`): plan, before and after state of every restart.

## 8. AI and untrusted data

The application contains **no AI component**, and none may be given SSH access. Any future AI
feature may only produce analysis or recommendations. Those must then go through an operation
request, the safety policy, the allowlist, validation and human confirmation, exactly like a user.
`test_architecture.py` fails if an LLM SDK is imported.

All switch output is untrusted data: descriptions, LLDP system names, MAC table fields and
`show system` text. Parsers extract structured values, and every answer must match its output
contract first. Any value that feeds a follow-up operation (a port or link-aggregate id from the
MAC table) passes the same strict validators as user input. Discovery accepts model and version
strings only if they match strict formats. Switch output can never change the policy, profiles,
permissions or settings. See `test_malicious_switch_output_never_becomes_a_command` and
`test_discovery_output_is_untrusted_data`.
